# midlife-article

## 目标

把一段中年人的真实经历写成一篇有人味、有因果深度、有哲学照明、能给读者带来现实帮助并改变一次选择的公众号文章。

文章不卖弄理论，也不把生活写成心理学课程。研究材料留在后台校准事实和边界，公开表达始终回到人物、关系、时间、责任、欲望、选择、得失与日常生活。

本技能不靠制造中年焦虑获取流量。文章可以诚实面对经济、职业、身体、家庭和社会环境的不如意，但必须帮助读者重新看清局面、找回可行动的部分，并获得有事实、有因果、有方法支撑的信心。

## 适用边界

只处理三十五岁以后的人生认知：

- 身体变化、健康觉醒与衰老；
- 父母老去、子女成长与代际关系；
- 婚姻、家庭、朋友、孤独和告别；
- 职业下半场、身份变化、尊严与失落；
- 时间、责任、欲望、后悔、取舍和重新开始；
- 用户提供的大段生活口述、个人经历或人生观察。

主题本质是技术讲解、产品教程、代码、架构、排障或实操方案时，使用`tech-article`；主题本质是科技商业、公司业务、产业竞争或业务投资判断时，使用`business-article`；其它一般主题使用`wechat-article`。不得借中年外壳进入本技能。

## 不可变契约

1. **只讲透一个人生问题**：一个具体事件只是入口，全文最终回答一个中年读者真正关心的问题。
2. **口述材料优先**：用户的动作、犹豫、原话和生活细节是叙事主体，外部资料不能把它淹没。
3. **深度来自因果**：下一层必须是上一层的因，上一层必须是下一层在现实中显现的果；并列概念、换案例、扩大范围和哲学类比不计入主下潜链。
4. **研究语言不进入正文**：理论名称只有在删除后会损害准确性时出现，并立即转译为没有专业背景的中年读者能直接理解的生活处境。
5. **哲学只负责照明**：东西方经典用于核对和拓宽规律，不为文化气息排队引用，不替代事实与因果。
6. **致用不写鸡汤**：读者读完必须获得一个选择原则、识别信号或现实动作，并知道它何时不适用。
7. **只保留一个中心判断**：正文不并列多个思想火花，不用固定口号和固定比喻统治全文。
8. **每张图同时呈现人和思想**：正文图默认标配双主角——男主`凝香`（约35岁、阳光开朗的中年男人）与女主`苏美`（约30岁、阳光开朗且贤惠气质的女性）。画风为半插画半真实的二次元细腻微3D，不追求摄影写实；人物神态必须积极向上、传递正能量，禁止长期忧愁、阴郁或受害者脸。上部约70%是丰富场景（饱满色彩、出色景深与光影），自然过渡到下部约30%精心设计的微3D信息提示。每张图带温和边框以形成画面边界感。每章一张3:4提示词，只生成提示词，不生成图片。
9. **标题与封面负责点击**：标题狠而熟；封面只做最贴合主题的完整场景与标题，不再使用信息卡或左右分栏信息图。封面同样是凝香与苏美的半插画微3D世界，人物阳光积极，环境丰富、色彩饱满、景深与光影出色，并带温和边框。标题与封面必须表达同一个点击核，正文真实兑现。
10. **作者先于经典**：先从故事独立形成一个人生命题，再以东方哲学为主、西方哲学为辅进行照明、补充或挑战，最后必须回到作者自己的综合判断。
11. **直白而有文艺范**：意思必须一遍读懂，文字可以有画面、节奏和余味；文艺感来自生活细节和克制表达，不来自生僻词、堆意象或散文诗排版。
12. **人称分层，不训人**：故事层默认用`他/她`（或凝香、苏美）承载现场；每章至少一次自然切到`你`做认出、追问或判断；回升与结尾以`你`交付动作。`我们`只偶发共情，禁止当全文主叙述。禁止“你必须”“你还不懂”一类训诫第二人称。
13. **开篇先硬钩再落现场**：前两三句必须先用一个熟悉现象、痛点或主题判断把读者砸进文章，再立刻落到具体人、动作或现场；禁止慢热氛围开场，也禁止只砸空洞金句却不兑现故事。硬钩靠不可否认，不靠恐吓与羞辱。
14. **帮助先于刺痛**：痛点只负责让读者认出自己，不能成为文章最终交付；每篇只选择一个主要帮助，明确读者读完能够恢复或提高什么。
15. **信心必须有根据**：不否认大环境和现实约束，也不许用空泛鼓励粉饰困难；信心来自更准确的判断、仍可改变的因果环节、可执行的第一步和能够观察的反馈。
16. **拒绝焦虑驱动**：不得使用灾难化未来、年龄羞辱、关系恐吓、收入羞辱或虚构恶化迫使读者行动；文章读完可以让人沉思，但不能只留下无力、内疚和恐惧。
17. **帮助范围明确**：主要帮助可落在认知与判断、情绪稳定与生活秩序、职业选择与收入能力、家庭与社会关系、身体照顾与时间安排等方向；主题不同可以出现其它帮助，但必须具体、现实且与因果主链相连。
18. **沉重之后必须回升**：中前段允许持续下潜，让读者看见人生处境真正的重量；最低点之前不急着安慰，最低点之后必须以认知重构、现实支点和可验证行动把读者带回地面。
19. **低负担不等于低密度**：文章让没有专业背景的读者顺畅读懂，但不删掉关键因果；一句一行、短段落和生活语言负责降低进入成本，每个句行仍必须推进事实、因果、感受或判断。
20. **许可必须保留责任**：文章可以帮助读者放下没有依据的自责、羞耻和内耗，但不能把逃避包装成通透；必须同时说清哪些并非他的错、哪些仍需要他作出选择。
21. **活人感来自真实处境**：声音来自用户经历、作者取舍、判断变化和仍未想通的部分，不靠假细节、口头禅、粗口、固定反转或刻意表演随意。

具体人格与语言只读取`references/author.md`。

## 流水线

完整文章依次完成S0-S6，S7逐图旁白与语音可选。用户已经给定主题、经历或口述时从S1开始；用户要求完整公众号文章时必须走到S6。

| 阶段 | 必读文件 | 核心产出 | 校验 |
|---|---|---|---|
| S0 选题 | `references/stage0.md` | 三个中年人生候选问题 | `validate_stage.py --stage 0` |
| S1 人事与见事 | `references/stage1.md` | 文章蓝图、逐篇说话位置、可叙事材料、事实与边界 | `validate_stage.py --stage 1` |
| S2 因果下潜与Spark | `references/stage2.md` + `author.md` | 五至七层因果主链、思维导图、一个Spark | `validate_stage.py --stage 2` |
| S3 悟道与致用 | `references/stage3.md` + `author.md` | 因果复核、哲学对照、现实帮助设计 | `validate_stage.py --stage 3` |
| S4 成文与HTML | `references/stage4.md` + `author.md` | 两遍成文后的定稿Markdown与可复制HTML | `validate_stage.py --stage 4` |
| S5 正文配图 | `references/stage5.md` | 每章一条3:4配图提示词 | `validate_stage.py --stage 5` |
| S6 标题封面摘要 | `references/stage6.md` | 标题、2.35:1封面提示词、digest | `validate_stage.py --stage 6` |
| S7 逐图旁白与语音，可选 | `references/stage7.md` + `author.md` | 每张正文图五至六句旁白、Edge TTS音频、时长清单与待放图片目录 | `validate_stage.py --stage 7` |

进入每个阶段前必须完整读取对应参考文件。不得凭记忆复述流程，也不得跳过阶段收据直接写最终文章。

## 阶段职责

- **S0只选择值得帮助的现实问题**，确认读者能否立即认出自己、可能获得什么以及为什么愿意转给一个具体的人，不预写结论。
- **S1确认人、事、处境、冲突、边界、本篇唯一的主要帮助和读者契约**，不堆心理学和医学科普。
- **S2建立因果深井、前哲学人生命题并培育一个Spark**，每次下潜都保留真实行动空间，并区分不必要的自责与不能逃避的责任，不写正文。
- **S3逐层审核因果，完成东方主照明、西方补维度、作者再综合、信心依据、许可边界、阅读减负与致用设计**，不写正文。
- **S4把已经验证的材料写成文章**，以硬钩开篇、分层人称和低阅读负担完成“被理解 → 看清楚 → 放下错误负担 → 找到支点 → 愿意行动”的阅读变化，不临时发明新机制。
- **S5只做正文图提示词**，每张图都以上约70%凝香苏美半插画场景与下约30%微3D信息层共同完成，人物始终积极向上。
- **S6独立完成标题、封面和摘要**，封面只做完整主题场景与标题，点击力来自熟悉处境、真实帮助和认知缺口，不靠恐吓。
- **S7围绕S5逐图重组连续口语叙事并生成同编号语音**，让视频也完成从困境到现实支点的回升，不生成图片、不合成视频。

## 阶段事务

S1-S6必须逐阶段执行，禁止先生成全部文件、最后补收据：

1. 进入阶段前，确认上一阶段收据存在且仍与当前上游内容匹配；
2. 只写当前阶段声明的业务产物；
3. 立即运行`python skills/midlife-article/scripts/validate_stage.py --stage N --topic-dir /absolute/topic/path`；
4. 只有命令返回`status=passed`且脚本生成当前收据，才可进入下一阶段；
5. 校验失败时停在当前阶段，修复后重跑，不得用说明文字代替成功。

`stage*_receipt.json`只保存校验元数据，不是内容容器。LLM不得创建、覆盖、复制或补写任何收据；S2、S3的新增内容必须写回`research/source_pack.json`。

## 执行纪律

- 用户要求完整文章时也必须逐阶段完成，不能把S1-S6合并为一次生成。
- 阶段完成后立即运行对应校验；失败时停在当前阶段。
- 收据只能由`validate_stage.py`生成，且绑定当前技能协议版本。
- `final_article_copy.html`只能由`scripts/markdown_to_wechat_html.py`从`final_article.md`生成。
- HTML不泄漏DATA、USER、DESCENT、SPARK、REBOUND或IMAGE施工标记。
- 在线研究先用Google发现国外原始页面，再保存真实页面；搜索摘要不进入证据池。
- 用户口述单独建账，只证明用户这样经历或表达过，不自动证明普遍规律。
- 没有执行校验或缺少任一必需收据时，只能报告“流程未完成”，不能宣布文章生成成功。
- 不生成流程未声明的报告和临时说明文件。
- S7通过后，用户只需把S5正文图片按对应ID放入`video/images/`；整个`video/`目录随后可由`narrated-video`直接消费。
