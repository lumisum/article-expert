# Stage 7：出镜口播文案

进入本阶段前完整读取本文件。Stage 7 是可选阶段，只生成一份可直接照着录制的中文口播文案，不生成配图、音频、字幕、时间轴或视频。

## 输入与目标

读取：

- `research/source_pack.json`
- `source_pack.json.article_profile`；口播的核心受众、现实入口、帮助形态和立场强度必须服从同一文章类型；
- `source_pack.json` 中与视频切口有关的 `observation_cards`、`mechanism_cards`、`spark_verdict`、`wisdom_candidates`、`practice_design` 及对应 `raw_pages/`

口播视频要在轻松、自然的几分钟里独立讲清一个问题。它不是文章摘要，也不能故意隐藏基本答案只做悬念引流；观众即使不阅读文章，也应听懂视频自己的事实、机制、判断和结论。

口播直接依据研究材料独立选择最适合视频表达的切口、推进顺序和具体措辞，并保持与 `author.md` 一致的作者人格。不得读取文章结构后逐段改写。

目标时长为正常口播速度下 3-5 分钟；用户未指定时默认写到 4-5 分钟，避免刚把问题说开就结束。时长由实际可说性决定，不按固定文章压缩比例生成。

默认校验按 4-5 分钟执行。只有用户明确要求约 3 分钟时，准出命令增加 `--min-seconds 180`。

## 镜头前的立场

动笔前在内部确定四件事，但不把它们写成提纲：

- 我对这件事最明确的判断是什么；
- 我反对或警惕哪种流行说法；
- 我希望观众看完采取什么判断或行动；
- 哪些事实还不足以让我下更重的结论。

口播前 20 秒内必须让观众听见清楚的问题或判断，而不只是背景、数据或名词介绍。自信来自明确结论和证据，不来自提高音量、连续反问或贬低不同意见。心态应当平和：理解观众为什么关心，再带着他把事情讲清楚。

第一人称只用于真实判断，例如“我的看法是”“我不建议这样做”；不得虚构亲历、客户案例或个人实验。说话者要有稳定人格，但不表演权威。

## 改写方法

1. 从已核验的见事、究理、主Spark、悟道与致用材料中独立选择一个中心问题、一个核心判断和两到三次关键推进，不沿用文章目录，也不逐段压缩文章形成同构复述。口播可以采用不同入口，但不能绕过挑战过程重新制造一个未经验证的新Spark。
2. 开头几句话直接进入本题最有吸引力的现场、问题、结果、事实或判断；热点数据只能辅助内容，不能代替人与人的交流。
3. 根据题材选择最自然的推进方式。技术与方法内容重目标、阻力、解决和验证；商业与事件内容重动作、因果、取舍和影响；人生与哲理内容重观察、解释、反例和判断。每隔一小段交付新事实、新解释或新判断，不能连续铺垫。
4. 把研究材料消化成现实中能自然说出口、且贴国内听感的话（标准见 `author.md`）。句子长短随内容变化，段落为换气服务，不追求整齐对称。
5. 数字、专名和专业术语要适合直接朗读；必要时换成听觉上更容易理解的中文表达，但不能损失准确性。举例优先落在国内观众熟悉的入口。
6. 网络感来自具体、直接、松弛和真实观察，不靠固定热梗、夸张情绪、粗俗用语或假装和观众吵架；禁止英文译稿腔与外文类比硬植入。
7. 结尾先完成视频自己的结论，再用一句自然的话把感兴趣的观众引向公众号文章。只导流一次，不在正文中反复预告文章，也不声称视频故意省略了答案。

口播内部同样要回答“发生了什么、为什么、意味着什么、可以怎么做”，但不念出“见事、究理、悟道、致用”这些层名。视频篇幅较短，哲学描述只在能快速照亮核心机制时使用；优先使用 Stage 1 已核对的准确中文，通常不超过一到两处，并用口语解释它为什么与本题相关。不能为了显得深刻而插入名言，也不能让哲学引用挤掉事实、机制和视频自己的结论。

## 情绪曲线

平和不等于平。整篇应有自然的情绪和理解变化，但不规定必须先认同、再反对、最后安慰。变化由事实、代价、行动、发现或选择推动，不使用煽情形容词替代内容。

面对镜头时，观众留下来往往不是因为主播年轻或热闹，而是因为他看起来真诚、笃定、没有浪费时间。口播应当让人感到：这个人有自己的判断，但没有急着压服我；他说得清楚，也愿意承认边界。

## 口语肌理

口播稿必须听起来像一个人正在和观众交流，而不是把书面文章朗读出来。根据上下文自然使用语气词、接话词和停顿，但不设固定词表或数量：

- 用简短语气词表达确认、缓冲、转念或亲近感，不能让每句话都端得过于完整；
- 用“你看”“说到这里”“换句话说”这类交流动作接住观众，而不是只靠逻辑连接词推进；
- 允许短暂自我修正，例如先说一个直观判断，再补一句更准确的表达，让思考显得真实；
- 在重要判断前后使用短句、逗号、句号、问句和自然分段形成停顿，不写括号式舞台指令；
- 停顿前后必须有语义作用：给观众消化、强调立场、转换视角或制造期待，不能只是装饰；
- 同一个语气词或接话句不能反复出现。通读时应像自然谈话，而不是背诵一套主播句式；
- 语气词不能削弱自信。需要明确判断时直说，缓和的是交流姿态，不是事实立场。

逐段朗读检查：如果去掉文字内容只看句式，整篇仍然像演讲稿、新闻解说或配音旁白，就继续改，直到能想象一个真人在镜头前自然说出这些话。

## 去 AI 味

完成后直接精修正文，不输出检查报告：

- 删除换个主题仍然成立的万能句；
- 删除重复总结、机械反转和过度解释转场；
- 不连续使用结构相同的短句制造虚假节奏；
- 不替观众规定情绪，让事实和细节自己产生反应；
- 逐段朗读，修正拗口语序、堆叠定语和现实交流中不会出现的表达；
- 保留说话者的判断和温度，但不表演人设。
- 使用国外材料时直接说准确的中文含义，不朗读英文原句，也不逐条播报来源；来源身份确实影响判断时再自然点名。

## 产物

只生成：

```text
video/talking_script.txt
```

文件必须是可以从第一句直接开始录制的纯文本：

- 不写标题、章节名、Markdown、镜头说明、括号舞台提示或时间码；
- 使用自然段和中文标点表达停顿；
- 不附创作说明、时长说明、摘要或备选版本；
- 内容必须与研究材料中的已核验事实一致；
- 正常口播估算时长应在 3-5 分钟。

## 准出

```bash
python skills/wechat-article/scripts/validate_talking_script.py --topic-dir /absolute/topic/path
```
