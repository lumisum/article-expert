# Stage 4：最终成文与HTML

进入本阶段前完整读取本文件和 `references/author.md`。S4只负责把已经通过S3验证的机制、Spark、悟道和致用组织成一篇自然、可信、值得读完的文章，再生成清爽、可复制的HTML。不得一边成文一边临时发明核心规律、哲学解释或实践方法。

遇到强事实、数字、原话或论证断点无法回查时暂停写作，返回对应研究阶段补足。Google结果页和摘要不作为证据。

最终产出：

1. `article/final_article.md`
2. `article/final_article_copy.html`

## 准入

必须同时存在：

- `research/stage1_receipt.json`
- `article/stage2_receipt.json`
- `article/stage3_receipt.json`
- `research/source_pack.json`
- `article/article_mindmap.md`

完整读取`descent_spine`、`spark_verdict`、`wisdom_synthesis`、实际采用的`wisdom_candidates`、`practice_design`、机制导图和全部直接相关的原始页面。S3材料仍然空泛时退回S3，不能靠漂亮文字补洞。

同时读取`article_profile`：

- `life_insight`以口述现场和作者判断带路，理论退居后台。正文要让35岁以后的读者感到“这说的就是我不愿承认的那一部分”，但不替读者诊断、不制造年龄焦虑。章节推进依靠人生处境被逐层看穿，不能写成“现象—心理学概念—名人名言—三条建议”的科普模板。
- `life_insight`只把S2的`reader_facing_expression`写进主要叙事。研究术语用于防止作者说错，不用于展示作者懂得多；确实无法删除的专业名称只出现一次，并立刻回到人物、关系、时间、责任、选择和生活后果。语言是否合格以目标读者能否直接理解为准。
- `event_business_investment`让事件在前段迅速退场，中段集中拆钱、角色、激励、壁垒、预期和风险，结尾交付观察框架。
- `practical_playbook`保留作者亲自做过的操作顺序和失败现场，核心主体按多个小目标迭代推进，读者应能边读边操作。

HTML同样继承文章模式。`life_insight`必须由转换器生成`data-wa-theme="life-insight"`主题，使用人生杂志式标题、时间轴章节、生活记忆式引用和克制的暖铜/雨蓝视觉；不使用技术蓝标题、虚线图片框、整页背景或模型手写`<style>`。S4不得自行拼装另一份HTML模板。

## 数字发布协议

正文中的金额、比例、份额、估值、排名、数量、日期、周期、技术尺寸和任何由数字推导出的比较，必须来自 `source_pack.json.numeric_claims`，不能直接从观察卡、新闻正文或作者心算进入成稿。

- 每个包含事实数字的Markdown内容块前，添加独立不可见标记：`<!-- DATA:N01 -->`；同一块引用多个数字时写作 `<!-- DATA:N01,N02 -->`；
- 标记必须紧贴它所支持的段落、列表或表格，不能隔着标题、图片占位或其他正文；
- 正文必须原样使用账本的 `publish_text`。要改单位、币种、分母、时间范围或计算方式，先更新账本并重新完成多方比对；
- `exact`才可写确定值；`range`只能使用核验后的区间；`attributed`必须明确这是哪一机构、哪类报告或哪一方的估算；`omit`不得出现；
- 两个来源引用同一篇通讯稿、同一份财报或同一数据库，不等于两个独立事实，只能算复核转述；在`independence_note`中写清共同上游；
- 不得混用交易日、季度、年度数据，不得混用销售额份额与出货量份额，不得混用总股本与流通股，不得把公司市值与未独立上市的业务分部市值比较；
- 换手率、渗透率、增长率、占比、倍数等必须明确分母；自行计算的结果必须在`calculation`中保留公式和输入值；
- 遇到无法解释的来源冲突，不取平均数凑答案。写区间、带来源归因，或者不写。

代码示例、章节编号、图片编号和纯粹的操作步骤序号不属于事实数字，不添加DATA标记。HTML转换器会移除这些施工标记。

用户口述中的个人时间、年龄、金额或次数不进入外部数字账本。在对应内容块前添加独立标记`<!-- USER:U01 -->`，ID必须来自`source_pack.json.user_materials`。该标记只表示“这段来自用户口述”，不能替这段中的外部统计、医学阈值或普遍性数字免责；同一段混有外部数字时必须拆段，并分别使用`USER`和`DATA`标记。HTML转换器会移除`USER`标记。

## 最终成文

### 内部认知配比

动笔前以以下中心比例安排认知重量，不写成可见栏目，也不由脚本机械计数：

- 见事约15%：只留下进入中心问题不可缺少的事实；
- 究理约45%：用最多篇幅解释变量、约束、因果、反馈、替代解释和边界；
- 悟道约20%：提炼规律，以哲学对照加深理解；
- 致用约20%：交付可以复用的判断、行动或观察方式。

如果见事超过约20%，优先删除背景、时间线和旁支；字数不足时补究理与致用，不补新闻材料。

### 章节组织

默认使用5–7个`##`大章节，约6章最容易形成稳定阅读节奏；题材天然更紧凑或需要更长推演时可以偏离。章节标题来自本篇具体问题、机制变化、规律或现实动作，不使用“见事、究理、悟道、致用”和“第X章”。

内部结构应当让读者经历：

> 看见熟悉异常 → 表面答案短暂成立 → 新问题击穿表面答案 → 连续下潜到结构、约束与代价 → 在最低点看清不可回避的规律 → 用简单判断与现实抓手迅速回升

这是一条认知曲线，不是固定六章标题。事实入口通常不超过一个主要章节，究理应构成中段主体。章节数量服从内容；有效下潜可以跨段发生，也可以一章完成多次，不能机械地把“一层”写成“一章”。

### 一口气下潜

- 动笔前先把 `descent_spine` 的 `L1…Lx` 映射到正文推进位置；每层至少有一个实质段落兑现，但层级标签不写入正文；
- 正文必须遵守主链顺序，可以把相邻层合并进同一章，也可以让一层跨越多段，但不得跳层、倒序或把各层改写成并列观点；
- 相邻层的正文转场必须保留“上一层是果、下一层是因”的关系。每次进入下一层，实际回答的应是“是什么让上一层发生或持续”，不能只用“还有一个原因”“从另一个角度看”切换栏目；
- 在每层第一个实质段落前写不可见施工标记 `<!-- DESCENT:L1:M01 -->`，层号和机制ID必须与 `descent_spine` 对应；开始悟道与致用回升前写一次 `<!-- REBOUND -->`。这些标记只用于校验，HTML转换器会移除；
- 第一章只打开中心问题，不给完整答案；
- 每个阶段性答案后，立即指出它仍解释不了什么，并自然进入下一层；
- 越接近最低点，叙述越具体、变量越少、约束越清晰，不靠更宏大的词制造深度；
- 反例不能单独摆成礼貌性的平衡章节，要用于击穿浅层解释或暴露真正代价；
- 在最低点前不提前总结、升华或给行动清单；
- 最深一层完成后、开始回升前写不可见标记`<!-- SPARK:S01 -->`，下一段必须原样包含`spark_verdict.publish_thesis`；随后再写`<!-- REBOUND -->`进入悟道与致用。HTML转换器会移除这些标记；
- Spark判断紧贴最低点出现，悟道负责挑战和照明，随后用一句极简判断继续回升；
- 回升只保留真正能改变判断或行动的抓手，不复述下潜过程。

文章产生的“压迫感”应来自证据和因果逐步收紧，让读者越来越难用原来的理解逃开；不得依靠灾难化、恐吓、绝对化或连续情绪形容词。

### 作者感与表达

- 作者负责选择、解释、判断和转场，不做来源播报员；
- 使用适合朗读的自然中文，直白、松弛、有分寸；
- 技术细节不能被网络话术稀释，商业判断不能用情绪替代证据；
- 不预设口头禅、热梗、反转句和固定比喻；
- 不使用粗俗脏话；
- 国外原文直接使用准确中文，不先展示外文再翻译；
- 事实、解释、推断和作者判断保持清晰边界。

### 证据消化与发布边界

研究材料必须在后台可回查，但发布正文不是论文：

- 不使用 `[^1]` 一类脚注标记，不生成尾注、参考文献、来源汇总或链接清单；
- 来源身份确实影响可信度时，在正文中自然说明机构、研究者、原典或报告类型，不另设出处段；
- 群体平均、相关关系和发展框架只能说明一种可能机制，不能直接推断某位读者必然如此；
- 用户口述用作者主体忠实复述，不加“据研究”腔，也不要求网页佐证；但从个人经历走向群体判断时必须明确完成证据换轨，不能把“我的故事”悄悄变成“人类规律”；
- 已有理论使用准确名称和适用边界；作者为了帮助理解而提出的新说法、概念或比喻，必须明确是本文的概括，不能写成学界已有定论；
- 比喻负责照亮机制，不能代替机制。一个比喻连续承担解释、判断和行动方案时，至少有一处返回具体变量、现实场景或反例；
- 同一个自造比喻、核心名词或口号连续出现时检查它是否已经替代了推理；一旦读者开始注意比喻本身而不是文章对象，就删减或换回具体场景。不得把某个传播词贯穿成整篇文章的人工概念系统；
- 哲学候选可以多，正文只保留真正推进推理的最少材料。连续引用多个思想家得出同向结论时，优先留下差异最大、解释力最强的一至两处；
- 涉及心理、健康、法律、财务和安全边界时，不依靠常识自行给出诊断阈值或操作建议，回到可靠指南核验后再写。

### 开头与收尾

开头从具体事实、场景、异常、问题或结果进入，尽快抵达中心问题。禁止报告摘要、新闻播报、背景大全和帮助清单。

收尾完成回升后的自然收束：回到开头的对象或场景，用一句清楚、轻盈但已经无法轻率反驳的判断收住。读者应感到视野重新打开，而不是又听一遍总结；不另开宏大主题，不用互动问题代替现实帮助。
结尾只允许一次真正收束。已经回到开头现场并完成行动后，不再追加“最后一句”、二次金句、互动追问和换一种说法的总结。

### 语义排版

内容稳定后再添加：

- `##`：大章节；
- `###`：必要的章内层次；
- `**重点**`：关键词或短判断；
- 独立 `**整句重点**`：少量核心结论；
- `>`：原话、核心判断或文末互动；
- 列表：步骤、条件、比较和检查项；
- 表格：确需横向比较的数据；
- 代码围栏：可复制的代码、命令或配置。

视觉丰富来自语义变化，不来自装饰堆叠：

- 每个主要章节都主动寻找至少一个适合独立成段的追问、转折或判断，让长段之间出现自然换气；句子必须本身有推进作用，不能为排版把一句完整意思机械切碎；
- 一句一段与中长段交替使用。连续多个短句只有在节奏确实需要时出现，不能把正文写成诗行、口号墙或短视频字幕；
- 一个连续段落区不要反复使用同一种独立粗体重点块；
- 机制内部确有层次时使用 `###`，让读者获得一次清楚换气；
- 原话、最低点判断或真正值得停顿的句子可以使用 `>`，普通结论不滥用引用；
- 并列步骤、条件、信号和对比优先使用列表，避免连续写成“第一、第二、第三”的同形段落；
- 只有横向比较确实更清楚时才使用表格，技术材料确实需要复现时才使用代码；
- 根据内容自然组合语义组件；没有语义需要时，不为排版丰富度硬凑列表、引用或小标题。

HTML转换器会按文章配图的主色和辅助色建立专属配色，并根据短重点句、长重点句、引用、列表和小标题生成不同视觉节奏。S4必须先在Markdown中表达正确语义，不能指望脚本替内容制造层次。正文不写图片占位，S5负责插入。

## 五、成文前的无报告审校

在写入最终文件前由LLM内部完成，不生成审校报告：

1. 给正文各段判断其主要属于见事、究理、悟道还是致用；
2. 见事是否过长，究理是否是最大主体；
3. 相邻段落是否形成“回答上一问 → 暴露更深问题”的连续下潜；
4. `L1…Lx` 是否按顺序全部兑现，是否有某层被跳过、倒序或摊平成并列论点；
5. 每一对相邻层是否仍能反向读成“因为下一层，所以出现上一层”，删除下一层后上一层是否失去关键解释；
6. 最低点是否触及真正的约束、代价或悖论，并同时解释积极与消极；
7. 核心问题是否被机制真正回答；
8. 悟道是否从最低点提炼出可迁移规律；若使用哲学对照，是否同时交代联系与差异边界；
9. 主Spark是否来自最低点附近，是否经最强反方后仍成立，正文是否只兑现一个主Spark；
10. 致用是否用极简判断开启回升，并包含场景、动作或信号、验证和边界；
11. 标题将来能够承诺的帮助是否已经被正文兑现；
12. 强事实、实际使用的哲学引用和实践依据是否能够回查；
13. 逐块扫描金额、比例、日期、排名、份额、倍数与派生比较，是否都带DATA标记并逐字符合`publish_text`；
14. 群体研究是否被误写成个人命运，用户口述是否被扩写成普遍规律，作者概括是否冒充既有术语，哲学材料是否形成排队背书；
15. `life_insight`是否已经把研究术语消化成目标读者凭生活经验就能理解的表达；
16. 正文是否出现脚注、尾注、参考文献或来源清单；
17. 不合格时直接重写相应部分，再保存最终文件。
18. 人生认知是否有刺、有温度、有现实代价，又没有被理论稀释；科技商业是否形成判断，科技实操是否真的可以抄作业。

## 篇幅与HTML

- 定稿以约3500个非空白字符为常用目标，不设跨题材统一硬下限；明显偏短时只补究理、反例、边界和致用过程；
- 见事从简，究理与致用决定深度；
- 最后一章精简；
- 运行 `markdown_to_wechat_html.py` 生成唯一的 `final_article_copy.html`；
- 全部可见文字统一15px；
- 使用内联CSS，不依赖整页背景；
- HTML声明UTF-8；
- HTML不得出现任何`<!-- DATA:... -->`、`<!-- USER:... -->`、`<!-- IMAGE:... -->`、`DESCENT`、`SPARK`、`REBOUND`或其转义文本；施工标记只存在于Markdown协议层；
- Markdown和HTML均不得出现脚注引用、脚注定义或文末来源附录；
- 首段渲染为 `opening-lead`；
- 文末确有讨论价值时才使用互动引用块，邀请语由本篇自然生成，后接1–3个短问题，不写账号名称。

## 准出

```bash
python skills/wechat-article/scripts/validate_final_outputs.py --topic-dir /absolute/topic/path
```

脚本只验证文件、研究协议、施工标记、数字账本绑定和HTML转换完整性。章节节奏、篇幅是否足够、语义组件选择、机制深度、悟道质量与现实帮助由上述LLM审校负责。
