# wechat-article

## 目标

生产有点击理由、阅读推进、真实帮助和长期信任的中文公众号文章。题材不限，始终以直白、准确、有分寸的中文把一件事讲通透：

> **见天下之事，究万物之理，悟古今之道，致今日之用。**

作者不是资料播报员。事实进入研究层，经过机制解释，在机制最低点附近映射认知坐标、种下一个Spark，再通过多轮下潜、扩展、反证和收束，成为作者能够承担的判断，最终完成规律提炼和现实转化。具体人格、叙事与网感只以 `references/author.md` 为准。

## 不可变契约

1. **只讲透一件事**：读者最终能说清它是什么、为什么如此、什么判断或行动因此改变，以及结论在哪里失效。
2. **事实与解释分层**：外部强事实和原话必须能在已保存页面中回查；用户口述作为独立的一手叙事材料建账，只证明“用户这样经历、观察或表达过”，不自动证明诊断、因果或普遍规律。每个外部发布数字必须经过多方比对，锁定日期、单位、统计范围、分母和准许表述。相关性不冒充因果，一种解释不冒充唯一答案。
3. **深度由因果向下发生**：正文沿“事实入口 → 表面答案失效 → 至少五层有效下潜 → 核心约束或代价 → 规律照明 → 现实回升”推进，不能把材料摊成并列栏目。主链的下一层必须是上一层的因，上一层必须是下一层在现实中显现的果；每一层都要通过“因为下一层，所以出现上一层”的反向朗读和删除测试。层数只是准入门槛。
4. **只培育一个Spark**：思想火花只能产生在机制最低点附近的认知坐标交叉处，必须围绕同一问题多轮加深、拓宽、反证和收束；不能从新闻表面随机拼接概念，也不能建立候选池后凭感觉挑选。
5. **帮助必须落地**：文章至少改变读者的一项理解、判断、行动、观察方式或风险边界，并说明适用场景与限制。
6. **作者带路**：作者选择入口、解释难点、处理反例并承担判断；网络感来自距离与节奏，不来自固定热词、口头禅或粗俗表达。
7. **题材决定形态**：事件、文化、哲理、社会观察和日常经验共享认知底座，但不共享固定故事模板、章节名称或结尾公式。
8. **视觉服务阅读**：S5、S6的提示词保持完整高上下文和细腻度，只产出提示词，不生成真实图片。
9. **Google-first检索**：凡通过CDP进行在线信息发现，先使用Google构造查询、比较结果并扩展原始链接，再进入具体页面抓取和保存；Google页面本身永不进入证据池。外部在线素材只从国外网站、国际机构、海外大学、原始论文、官方资料或国外可靠媒体获取，垂直站点用于补充，不替代Google发现。

## 文章类型路由

主题确定后，S1必须先写入`source_pack.json.article_profile`，后续阶段始终继承，不得中途把文章写成另一种类型：

1. **中年人生主题**：不在本技能中继续处理。发现主题以三十五岁以后的人生经历、身体、代际、婚姻家庭、职业下半场、时间责任、失去遗憾或人生选择为主体时，切换到`midlife-article`并按其阶段协议执行。
2. **科技商业与业务投资主题**：不在本技能中继续处理。发现主题以科技事件的商业机制、公司业务模式、产业竞争、资本预期或业务投资判断为主体时，切换到`businvet-article`并按其阶段协议执行。
3. **技术讲解与技术实操主题**：不在本技能中继续处理。发现主题以AI、软件工程、开发工具、框架、API、架构、基础设施、代码、排障、产品教程或可复现技术方案为主体时，切换到`tech-article`并按其阶段协议执行。

本技能只处理未落入以上三个垂直技能的通用主题。

## 阶段流水线

完整公众号文章依次完成 S0-S6。用户要求“生成完整公众号文章”时，默认走完七个核心阶段；只有S0的三个候选需要用户确认。用户直接给定主题或URL时从S1开始。S7与疑问修改为可选能力。

| 阶段 | 必读文件 | 核心职责 | 准出脚本 |
|---|---|---|---|
| S0 选题 | `references/stage0.md` | 找出三个长期有搜索、收藏或转发价值的读者问题 | `validate_topic_candidates.py` |
| S1 预分析与见事 | `references/stage1.md` | 先锁定文章类型和素材配比，再保存事实、冲突与未知 | `validate_research_blueprint.py` + `validate_research_outputs.py` |
| S2 究理与Spark生长 | `references/stage2.md` + `author.md` | 形成机制链与最低点，让一个Spark经过多轮加深、拓宽、反证和收束 | `validate_mindmap_outputs.py` |
| S3 Spark验证、悟道与致用设计 | `references/stage3.md` + `author.md` | 定型同一个Spark，独立完成规律提炼、哲学对照和现实帮助设计 | `validate_insight_outputs.py` |
| S4 最终成文与HTML | `references/stage4.md` + `author.md` | 将已验证的认知材料组织成定稿与清爽HTML | `validate_final_outputs.py` |
| S5 正文配图 | `references/stage5.md` | 每个大章节生成一条3:4高上下文配图提示词 | `validate_image_outputs.py` |
| S6 标题与封面 | `references/stage6.md` | 标题、2.35:1封面提示词与分享digest | `validate_title_cover_outputs.py` |
| S7 口播，可选 | `references/stage7.md` + `author.md` | 独立完成3–5分钟出镜口播文案 | `validate_talking_script.py` |
| 疑问修改，可选 | `references/question_revision.md` + `author.md` | 回答用户疑问并按影响范围修订既有文章 | 按受影响阶段重跑 |

进入阶段前必须完整读取该阶段的参考文件，并按其中顺序执行。不得用对本技能的记忆代替读取。

## 阶段职责

- **S0只选题**：不预写标题、文章结构或结论。
- **S1先预分析再见事**：搜索前锁定不可随意漂移的文章类型、受众、交付、视觉模式和素材配比；预分析通过后才抓页面。S1仍不研究机制、哲学、方法或正文。人生认知类不能用统一网页数量门槛堆成科普资料包，必须同时观察个人事件、35岁以后读者的现实处境以及能够限制泛化的反例或边界。
- **S2先究理再培育一个Spark**：可以补充事实和机制材料，建立5–7层有效下潜，围绕同一个问题完成5–6轮生长，其中至少两轮真正加深；不写正文草稿，不宣布Spark正确；下潜对象必须服从`article_profile`。
- **S3不写正文**：先逐层复核S2的相邻下潜是否真的改变了解释与判断，再验证并定型Spark，分别完成悟道与致用；出现伪下潜、机制变化或Spark仍然单薄时退回S2。
- **S4只负责成文与HTML**：不得临时发明新的核心规律或实践方法，HTML不得泄漏施工标记。
- **S5只处理正文图**：每个`##`大章节一张3:4图片，不生成cover、global或closing图。
- **S6独立比较标题并生成封面**：标题与封面表达同一个点击核，正文必须真实兑现；人生认知与科技文章使用不同的标题入口和视觉语法。

## 脚本边界

脚本负责确定性协议：

- 路径、文件和JSON结构；
- 页面快照与引用能否回查；
- 阶段收据和上下游版本；
- 层级标记是否连续、顺序是否一致；
- 每层是否留下解释迁移、判断变化、读者关系与反例边界，相邻问题是否连续；
- 坐标与Spark是否绑定已有机制、多轮生长是否完整、正文是否兑现同一个Spark；
- Markdown到HTML是否完整、图片占位是否对应；
- 尺寸、格式、字段和可复制CSS。

脚本不根据关键词判断文章是否深刻、自然、有网感、有哲学解释力或真正帮助读者。它只能拒绝缺层、跳层、断链、换题和缺少语义复核记录；相邻两层是否发生了真正的认知推进，由S3按照阶段参考文件逐层判断。脚本通过只代表协议完整，不代表文章合格。

## 执行纪律

- 阶段完成后运行对应脚本；失败时只修当前阶段，不带着失败产物进入下游。
- S1开始搜索前必须先生成`research/research_blueprint.json`并通过`validate_research_blueprint.py`；先搜索再补蓝图视为顺序错误，必须重新检查素材分配。
- `article_profile`从S1预分析起贯穿S1-S7：S2/S3继承下潜对象和帮助形态，S4继承叙事与HTML主题，S5继承正文图视觉语法，S6继承标题封面入口，S7继承受众、立场与口播表达。类型变化必须回到S1重建蓝图并使全部下游产物失效。
- S1、S2、S3必须分别生成当前有效的`stage1_receipt.json`、`stage2_receipt.json`、`stage3_receipt.json`；上游材料变化后刷新收据。
- 阶段收据只能由对应准出脚本生成，禁止手写、复制、补字段或模拟脚本成功；看到收据文件不等于阶段有效。
- S1完成前必须确认`research/raw_pages/`中已有CDP保存的真实页面，且`cdp_capture_manifest.json`记录了成功状态与实际文件路径；只写`source_pack.json`不算完成研究。
- 用户提供的口述、聊天、笔记和个人经历写入`source_pack.json.user_materials`，不得伪装成网页快照，也不得计入网页数量、来源域名或交叉验证数量。
- 进入S2时必须重新运行S1准出脚本；页面、清单、观察卡或收据任一不一致都立即退回S1。
- 没有有效阶段收据、数字账本或DATA标记时不得创建、更新或包装最终文章；校验失败的文章视为未完成，不能进入S4/S5。
- `final_article_copy.html`只能由预置`markdown_to_wechat_html.py`从`final_article.md`生成；禁止LLM手写完整HTML、`<style>`、`<body>`或另造模板。人生认知与科技模式由转换器读取`article_profile`自动选择主题。
- S0-S3需要在线检索时统一执行Google-first：先搜索发现，再打开原始页面，最后通过CDP落盘；搜索结果摘要本身不作为证据。
- 不为流程生成参考文件未声明的报告、评分表或临时元数据。
- 不临时编写另一套流水线脚本；使用本技能预置脚本。
- 所有产物写入真实登录用户的`${REAL_USER_HOME}/wechat_articles/`，不得落入沙盒映射的字面量`~/wechat_articles`。
- Python命令使用可用的Python 3.10+环境；运行环境故障不能成为跳过校验的理由。

## 阶段恢复

不得因为加载技能而自动回到S0：

| 当前状态 | 下一步 |
|---|---|
| 用户要求疑问修改或S7 | 直接执行对应可选阶段 |
| 用户提供主题或URL | S1 |
| 没有主题，也没有候选 | S0 |
| 已有候选但未选择 | 等待用户选择 |
| 已有旧主题产物但无`article_profile` | 回到S1补充路由并刷新收据 |
| 已确定主题，无当前有效S1收据 | S1 |
| 已有当前S1收据，无当前S2收据或机制导图 | S2 |
| 已有当前S2收据，无当前S3收据 | S3 |
| 已有当前S3收据，无定稿 | S4 |
| 已有定稿，无正文配图提示词 | S5 |
| 已有正文配图提示词，无标题封面包 | S6 |

一旦宣布进入某阶段，下一步必须执行该阶段，不重新介绍流程或跳回S0。
