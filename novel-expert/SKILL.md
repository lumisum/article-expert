# 小说专家

## 目标

把一个中年人生处境转化成苏美与凝香共同经历的一件事：先让事情发生，再让人物在动作、迟疑、误解、选择、代价和反馈中发生变化。读者从人物最终做了什么感到他怎样看待生活；全文可以没有一句总结道理的话，也不要求隐藏意义能够被压缩成一个观点。

文章不卖弄理论，也不把生活写成心理学课程。研究材料留在后台校准事实和边界，公开表达始终回到人物、关系、时间、责任、欲望、选择、得失与日常生活。

本技能不靠制造中年焦虑获取流量。小说可以诚实面对经济、职业、身体、家庭和社会环境的不如意，但不能靠羞辱、恐吓或宿命感操纵读者；希望若出现，必须从人物仍愿意做的事和生活给出的真实反馈中长出来。

## 适用边界

只处理三十五岁以后的人生认知：

- 身体变化、健康觉醒与衰老；
- 父母老去、子女成长与代际关系；
- 婚姻、家庭、朋友、孤独和告别；
- 职业下半场、身份变化、尊严与失落；
- 时间、责任、欲望、后悔、取舍和重新开始；
- 用户提供的大段生活口述、个人经历或人生观察。

主题本质是技术讲解、产品教程、代码、架构、排障或实操方案时，使用`tech-article`；主题本质是科技商业、公司业务、产业竞争或业务投资判断时，使用`business-article`；其它一般主题使用`wechat-article`。不得借中年外壳进入本技能。

## 不可变契约

1. **只让一件事真正发生**：一个具体事件就是小说主体，人物欲望、阻力、选择与后果都从这件事生长；中心问题可以留下余波，不强求全文给出标准答案。
2. **口述材料优先**：用户的动作、犹豫、原话和生活细节是叙事主体，外部资料不能把它淹没。
3. **深度来自行动因果**：人物相信什么，决定他怎样行动；行动造成后果，后果逼出新的选择。深度不来自五至七层抽象分析，而来自行为、代价、关系与认识连续改变。
4. **研究语言不进入正文**：理论名称只有在删除后会损害准确性时出现，并立即转译为没有专业背景的中年读者能直接理解的生活处境。
5. **参考信息只留在后台**：心理、社会、医学、哲学或其它资料只有在帮助理解人物、校准事实或收窄边界时保留；不强制检索经典，不因已经研究就写进正文。
6. **知行合一是人物弧**：人物最终的行为必须证明认识已经变化。只让角色说“我明白了”“以后会改变”，不算完成。
7. **只保留一层隐藏意义**：它用于导演故事，可以是认识、关系张力、生命体验或仍未解决的问题，不要求写成一句道理。默认通过人物选择、代价、关系反馈和结尾回声让读者自行感到。
8. **苏美与凝香是跨文章固定男女主角，不是全部角色**：完整读取`references/cast-bible.json`，两位主角的姓名、性别、年龄、外观、服装系统、声音、表情习惯、动作习惯、标志物和“长期内容搭档与朋友”关系均不得漂移。剧情需要时可自由增加配角；配角必须进入`supporting_cast`，具有材料边界、稳定身份和不可替代的事件作用。
9. **正文只有小说故事模式**：`narrative_mode`固定为`novel_story`，不再选择播客、对谈、访谈、纪实说明或其它模式。环境、动作、表情、心理和时间变化由作者旁白自然承载，人物语言只在人物确实需要开口时出现；不规定对话轮次与占比，不允许用轮流发言代替故事。
10. **开场先发生一件事**：正文前10%必须让读者自然看见时间、地点、在场人物、触发事件、人物的第一个可见动作和一个尚未解决的问题。禁止纯风景、纯感慨、人物背景介绍或中心观点开场；引子不是前言，而是后文必须继续处理的事件。
11. **故事就是表达**：场景、动作、冲突、关系反应、选择与反馈承担正文意义。默认不直接讲道理；确有必要时只允许一句轻旁白，且删除后故事仍能表达同一认识。
12. **触发事件必须首尾闭环**：开场的消息、物件、请求、决定或未完成动作必须持续影响中段，并在结尾得到行动、反馈或关系上的回应。禁止引子用完即丢、只在结尾口头宣告“以后会改变”，现实动作必须在读者眼前发生。
13. **封面与整组配图共用成熟彩色叙事插画微3D**：正文每章一张3:4、100%全画幅、0信息层的成人向连环画；每张图用6%至10%同世界纹理的窄荧幕边框承载一条4至14字的场景短句，短句只提示未完成动作、心声、物件或时间，不讲道理；封面和视频封面也有无文字边框，但事件标题必须留在场景原生负空间、绝不写进边框。画风固定为约65%成熟插画化、25%微3D材质、10%现实生活锚点，并以通透自然光、丰富环境色、前中后景和插画化空气透视制造镜头感；禁止写实摄影、真人写真和电影剧照。每幕只出现`characters_present`真正需要的人物，至少一位固定主角在场，配角按剧情加入；人物签名服从角色圣经或配角连续性合同，相邻图片延续动作、物件、光线或颜色。
14. **标题与封面必须事件化、完整场景化**：文章标题和封面主标题截取正文中一个正在发生、尚未结束的动作、来电、消息、请求、停顿或选择。文章与视频封面100%重现一张最能代表本篇小说的完整场景，标题进入墙面、窗光、天空或纵深等原生负空间；禁止5:5、70:30、左右分栏、标题板、信息卡、人物抠图拼贴和知识框架。至少一位固定主角可辨认，其余人物完全服从该场景。
15. **行动先于解释**：先让人物在现实中做出选择，再决定是否需要一句解释。任何经典、理论、作者判断或角色总结都不能替代行动证据。
16. **直白而有文艺范**：意思必须一遍读懂，文字可以有画面、节奏和余味；文艺感来自生活细节和克制表达，不来自生僻词、堆意象或散文诗排版。
17. **小说体验先于功能交付**：不预设读者读完必须获得一个方法、判断或第一步；作品的价值可以只是让一种处境第一次被准确看见，让一种复杂感受获得名字之外的形状。
18. **希望必须由情节成立**：不否认大环境和现实约束，也不许用空泛鼓励粉饰困难；希望来自人物仍愿意承担的行动、关系给出的反馈和生活中微小但真实的变化。
19. **拒绝焦虑驱动**：不得使用灾难化未来、年龄羞辱、关系恐吓、收入羞辱或虚构恶化迫使读者行动；文章读完可以让人沉思，但不能只留下无力、内疚和恐惧。
20. **意义不能凌驾于人物**：不得为了证明正确观点让角色突然开悟、选择显而易见的答案，或把另一个人物降格成反面教材。认识只能在具体处境、有限选择和真实代价中成立。
21. **结尾完成行动，不封死生活**：中前段允许持续下潜，结尾必须兑现开场事件并让人物实际做了什么，但结果可以不圆满、问题可以继续存在；不为“积极”强行成功、和解或顿悟。
22. **低负担不等于低密度**：文章让没有专业背景的读者顺畅读懂，但不删掉关键因果；自然旁白、必要对话和生活语言负责降低进入成本，每个叙事块仍必须推进事实、因果、感受、关系或判断。
23. **人物尊严与责任并存**：叙事不能羞辱、诊断或标签化人物，也不能把逃避包装成通透；角色即使误判、软弱或失败，仍拥有复杂动机，同时承担自己的选择和后果。
24. **活人感来自真实处境**：声音来自用户经历、作者取舍、判断变化和仍未想通的部分，不靠假细节、口头禅、粗口、固定反转或刻意表演随意。
25. **正文可见文字保持三千至六千字**：以三千至六千个非空白可见字符为硬范围，人物姓名计入但施工标记不计入。具体长度服从事件复杂度，不强行写满上限；增加篇幅只能用于事件过程、细微心理、声音、环境、身体反应、关系距离、选择前后的迟疑与现实反馈，禁止用背景科普、重复观点、平行案例或加长台词凑字数。
26. **细腻不是形容词堆积**：每个关键情节都要捕捉一个发生变化的微信号，例如呼吸变浅、句尾收住、目光移开又回来、手指停在发送键、杯底碰桌面的轻响、两人距离缩短半步；微细节必须改变判断、动作或关系，不能只是装饰环境。
27. **配图必须演出鲜明表情弧**：整组连环画在保持阳光和希望的同时，分别设计苏美与凝香从开场警觉或好奇、压力中的克制、看见真相时的微怔，到行动后的释然和结尾的明亮稳定。相邻两幕不得复制同一笑容、眼神、嘴角和身体姿态；两人在同一幕也要形成回应或反差，禁止全篇统一微笑脸和表情平铺。
28. **逻辑是知行合一的地基**：完整读取`references/story-logic.md`，逐项建立时间、知情、金钱物件、现实流程、动机备选、因果、伏笔回收与结局代价八本账。人物可以误判，作者不能误算；任一关键动作无法回答“为什么现在、为什么由他、为什么这样做、为什么产生这个结果”，就不得进入正文。
29. **HTML只有普通小说段落**：标题之外，旁白与人物语言全部使用`data-wa-format="author-narration"`的同一15px普通段落样式。人物语言保留“姓名：台词”的正文文字，但禁止人物标签、专属颜色、左边线、聊天气泡、字号差异或`character-dialogue`组件。

故事构思逻辑读取`references/story-logic.md`，作者边界读取`references/author.md`，固定人物、声音和视觉身份读取`references/cast-bible.json`。

## 流水线

完整文章依次完成S0-S6，S7逐图旁白与语音可选。用户已经给定主题、经历或口述时从S1开始；用户要求完整公众号文章时必须走到S6。

| 阶段 | 必读文件 | 核心产出 | 校验 |
|---|---|---|---|
| S0 选题 | `references/stage0.md` | 三个中年人生候选问题 | `validate_stage.py --stage 0` |
| S1 人事与见事 | `references/stage1.md` + `story-logic.md` + `cast-bible.json` | 小说合同、八本逻辑账、固定主角与动态配角、材料与边界 | `validate_stage.py --stage 1` |
| S2 小说内核与行动弧 | `references/stage2.md` + `story-logic.md` + `author.md` | 构思模型、三至五步行动因果、人物弧、知情变化与场景计划 | `validate_stage.py --stage 2` |
| S3 可写性与逻辑审计 | `references/stage3.md` + `story-logic.md` + `author.md` | 现实逻辑、行动证明、事实边界、非说教、反焦虑与结尾审计 | `validate_stage.py --stage 3` |
| S4 小说成文与HTML | `references/stage4.md` + `story-logic.md` + `author.md` + `cast-bible.json` | 小说故事Markdown与单一普通小说段落HTML | `validate_stage.py --stage 4` |
| S5 正文配图 | `references/stage5.md` + `cast-bible.json` | 苏美与凝香连续全场景连环画提示词，边框内仅一条场景短句 | `validate_stage.py --stage 5` |
| S6 标题封面摘要 | `references/stage6.md` + `cast-bible.json` | 核心故事标题、完整场景式文章与视频封面JSONL、digest | `validate_stage.py --stage 6` |
| S7 小说多人有声版，可选 | `references/stage7.md` + `author.md` + `cast-bible.json` | 按实际出场人物生成分段语音、每图合并音频与时长清单 | `validate_stage.py --stage 7` |

## 阶段职责

- **S0只选择真正能够长成小说的现实事件**，比较人物欲望、关系张力、行动代价、感官现场与结尾余味，不预写结论。
- **S1确认人、事、处境、冲突、边界、情感真实和预期余味**，同时锁定开场、贯穿锚点、“触发—摩擦—选择—回应”四拍与八本现实逻辑账，不建立痛点转化、帮助交付或读后改变合同。
- **S2把隐藏意义翻译成行动因果**，只选择一至两个经典构思逻辑模型，设计人物的旧认识、可靠新事实、行动代价、知情变化、现实后果和最终行动证明；同步完成人物弧、必要配角功能与四至六幕场景计划，不写正文、不做思维导图。
- **S3先审核逻辑、再审核意义**，逐项复盘时间、知情、金钱物件、现实流程、动机备选、因果承接、伏笔回收和结局代价，再检查事实边界、人物能动性、说教风险、反焦虑与结尾证明。
- **S4把已验证材料写成苏美与凝香共同经历的现实主义小说故事**，先发生事，再以环境描写、作者旁白和必要的人物语言完成“被卷入 → 发生摩擦 → 看清楚 → 当场行动 → 得到回应”；成文不得偷偷改动已审计的事实与逻辑，HTML统一为普通小说段落。
- **S5先完成整篇连环画导演设计，再写逐幕提示词**，固定主角与配角连续性、人物组合、关系动作、母题、阳光色彩、希望信号和相邻转场必须服从剧情；正文图100%为场景、0%为信息层，只允许一条融入窄荧幕边框的场景短句。
- **S6只围绕正文中一个正在发生且尚未结束的事件瞬间完成标题、文章封面、视频封面和摘要**，主标题事件化；封面是一张完整小说场景加自然融入的标题，不做比例切分或信息卡。
- **S7把每张图对应的小说片段重组为按实际出场人物表演的有声场景**，固定主角保持跨篇音色，配角保持同篇音色，再合并为每图同编号语音；它不是播客节目。

## 阶段事务

S1-S6必须逐阶段执行，禁止先生成全部文件、最后补收据：

1. 进入阶段前，确认上一阶段收据存在且仍与当前上游内容匹配；
2. 只写当前阶段声明的业务产物；
3. 立即运行`python skills/novel-expert/scripts/validate_stage.py --stage N --topic-dir /absolute/topic/path`；
4. 只有命令返回`status=passed`且脚本生成当前收据，才可进入下一阶段；
5. 校验失败时停在当前阶段，修复后重跑，不得用说明文字代替成功。

`stage*_receipt.json`只保存校验元数据，不是内容容器。LLM不得创建、覆盖、复制或补写任何收据；S2、S3的新增内容必须写回`research/source_pack.json`。

## 执行纪律

- 用户要求完整文章时也必须逐阶段完成，不能把S1-S6合并为一次生成。
- 阶段完成后立即运行对应校验；失败时停在当前阶段。
- 收据只能由`validate_stage.py`生成，且绑定当前技能协议版本。
- `final_article_copy.html`只能由`scripts/markdown_to_wechat_html.py`从`final_article.md`生成。
- HTML不泄漏DATA、USER、STORY、ACTION、MEANING或IMAGE施工标记。
- 在线研究先用Google发现国外原始页面，再保存真实页面；搜索摘要不进入证据池。
- 用户口述单独建账，只证明用户这样经历或表达过，不自动证明普遍规律。
