# S7：逐图旁白与语音

S7可选。它为S5的每一张正文配图生成一段贴图旁白，再直接调用系统已有的Edge TTS能力，按相同编号逐段生成MP3。S7不生成图片，不合成视频。

## 准入

开始前完整读取：

- `references/author.md`
- `article/final_article.md`
- `assets/image_prompts.jsonl`
- `assets/title_cover_package.json`
- S5和S6回执

必须逐行理解S5配图提示词中的章节语境、读者动作、画面上下层、信息问题、视觉桥梁和中文标签。旁白数量必须与正文配图数量完全一致。

开始时创建`video/images/`和`video/audio/`。`video/images/`保持为空，用户稍后只需把生成好的图片按S5图片ID命名后放入其中。

## 视频叙事

整组旁白共同讲清文章的一条核心技术路线，但每段只承担当前图片最适合讲透的一个问题：

1. 第一段快速进入真实技术处境，给出明确问题和继续观看的理由；
2. 中间各段承接上一张图留下的问题，沿机制、步骤、故障、修复或优化继续推进；
3. 最后一段完成验证、边界或行动收束，不重新总结整篇文章；
4. 视频可以独立成立，需要时只在最后自然提示完整步骤、代码和边界可在文章中查看。

不得把文章按章节压缩后逐段朗读。旁白必须重新组织成适合连续观看的口语叙事。

## 每段怎样贴合图片

每段旁白必须同时使用当前配图的场景层和信息层：

- 从上方真实技术场景中的一个具体对象、动作、错误状态或操作结果进入；
- 顺着共享主体或视觉桥梁，把注意力带到下方白色微3D信息结构；
- 用口语解释信息结构中的机制、顺序、因果、对比或排障路径；
- 说明读者看懂这张图后能少踩什么坑、完成什么判断或采取什么动作；
- 不逐项报菜名，不反复说“大家看这张图”，也不描述与技术理解无关的颜色、材质和装饰。

旁白中的技术含义必须与`image_meaning`、`visual_anchor`和S5原提示词一致。不得为了好讲而给图片添加不存在的模块、箭头、数据、结论或操作结果。

## 流畅、自然、风趣

每段使用五至六个完整中文句子。句数是主要长度标准，不为了凑字数拆短句，也不把多个独立意思用逗号硬塞成一句。

- 像一个懂技术、做过实操的人陪观众看图，不像TTS说明书、课程目录或文章摘要；
- 表达贴近中文互联网听感，轻松、有判断、有现场感；
- 风趣来自技术现实中的反差、踩坑、误判和解决后的释然，不靠堆流行语、固定段子、粗俗表达或刻意抖机灵；
- 专业名词只保留当前画面真正需要的部分，第一次出现时用口语说明它在做什么；
- 长短句交替，使用自然停顿和转折；语气词只能由上下文产生，不能每段机械重复；
- 不朗读代码、文件路径、长参数、网址和图中全部标签；只讲观众此刻必须理解的关键部分。

## 图片之间的衔接

全部旁白连读时必须像一段连续讲话，而不是若干独立短视频拼接：

- 除第一段外，每段开头承接上一段的结果、疑问或尚未解决的障碍；
- 除最后一段外，每段结尾自然留下下一张图要回答的具体问题、动作或后果；
- 过渡不能只写“接下来我们看”“下面进入下一部分”等空连接；
- 不在每次换图时重新介绍主题、复述标题或重复观看回报；
- 相邻两段连读时，人物指代、技术对象、时间顺序和因果方向必须连续；
- 每段结尾使用完整句和自然落点，避免音频切换时语气悬空。

先单独写`transition_in`和`transition_out`，再把过渡自然融入`narration`。这两个字段是连续性设计，不是额外朗读的提示语。

## 旁白文本产物

写入`video/narration_segments.jsonl`，每行对应一张S5配图：

```json
{
  "id": "section_1",
  "order": 1,
  "image_prompt_id": "section_1",
  "section_title": "与S5完全一致的章节标题",
  "image_meaning": "这张图真正要让观众理解的一个技术含义",
  "visual_anchor": "旁白将具体指向的场景对象、共享主体和信息结构",
  "narration_goal": "听完本段后观众获得的理解或动作",
  "transition_in": "怎样承接上一段；第一段说明怎样自然开场",
  "transition_out": "怎样把问题或动作交给下一段；最后一段说明怎样收束",
  "narration": "五至六个完整中文句子的可直接朗读旁白",
  "audio_file": "video/audio/section_1.mp3"
}
```

要求：

- 行数、顺序、`id`、`image_prompt_id`和`section_title`与`assets/image_prompts.jsonl`严格对应；
- `audio_file`固定使用相同图片编号；
- 每段只写可直接送入TTS的旁白，不写括号舞台提示、镜头指令、Markdown、时间码或字段说明；
- 写完全部旁白后，从第一段到最后一段连续朗读一遍，修复重复开场、对象跳变、因果断裂和生硬过渡，再生成音频。

## Edge TTS语音生成

旁白定稿后，直接调用系统已有的Edge TTS能力，严格按照`section_1`至`section_N`串行生成同编号音频：

`video/audio/section_1.mp3`

`video/audio/section_2.mp3`

依此类推。

要求：

- 使用用户指定或系统已配置的中文音色，不在文章内容中写死音色；
- 同一视频默认保持同一音色、语速、音量和音高；
- 每次只提交当前`narration`字段，不朗读其它结构字段；
- 当前编号音频成功保存后才进入下一编号，失败时只重试当前段，不能跳号、重号或覆盖其它段；
- 生成后确认MP3可读取且有实际时长；
- 音频文件名、旁白`id`和图片`id`必须使用同一编号。

## 音频清单

完成语音后写入`video/audio_manifest.json`：

```json
{
  "tts_engine": "edge_tts",
  "voice": "实际使用的中文音色",
  "rate": "实际语速设置",
  "volume": "实际音量设置",
  "pitch": "实际音高设置",
  "segments": [
    {
      "id": "section_1",
      "image_prompt_id": "section_1",
      "audio_file": "video/audio/section_1.mp3",
      "status": "success",
      "duration_seconds": 48.2
    }
  ],
  "total_duration_seconds": 286.4
}
```

`segments`数量和顺序必须与配图一致。`duration_seconds`记录实际音频时长，用于后续让每张图片按对应音频时长展示；`total_duration_seconds`为全部片段实际时长之和。

## 完成

运行：

`python skills/tech-article/scripts/validate_stage.py --stage 7 --topic-dir /absolute/topic/path`

只有旁白和音频数量与S5配图计划一致，编号严格对应，每段包含五至六个完整句子，全部MP3存在且清单状态成功，才可宣布S7完成。

通过后，向用户明确列出`video/images/`所期待的图片ID。用户把同编号PNG、JPG、JPEG或WEBP放入该目录后，可直接把整个`video/`目录交给`narrated-video`：

`python skills/narrated-video/scripts/build_narrated_video.py /absolute/topic/path/video`
