# S4：商业成文与HTML

完整读取`business_depth.md`、`author.md`、商业发动机、因果主链、因果审计、经济性审计、Spark定论、实际采用的规律材料和业务投资观察框架。

## 文章认知重量

- 科技事件约一成：只承担开门、制造矛盾和提供事实基线；
- 商业究理约六成：完整解释客户价值、付款、收入、成本、单位经济性、现金、竞争、产业权力和资本预期；
- 悟道约一成：用经济学、商业理论或哲学照亮最低层机制；
- 致用约两成：交付观察变量、正反信号和情景边界。

比例用于内部判断，不写成四个栏目。

## 结构

默认五至七个`##`章节。章节名称来自本篇业务冲突，不使用“见事、究理、悟道、致用”和“第X章”。

正文不固定套栏目，但认知顺序必须完成：

> 熟悉科技事件 → 表面科技叙事失效 → 客户为何改变 → 谁为何付款 → 收入怎样形成 → 成本与资本怎样吞吐收入 → 利润和现金能否留下 → 规模与竞争怎样重分配利润 → 资本在提前定价什么 → Spark判断 → 规律照明 → 观察框架

章节标题必须来自本题最有力量的商业矛盾。不能连续两章主要解释技术；不能用市场规模、订单、融资或估值跳过利润形成。

每层第一个实质段落前放：

```markdown
<!-- DESCENT:L1:C01 -->
```

最低点之后：

```markdown
<!-- SPARK:S01 -->
必须原样出现publish_thesis
<!-- REBOUND -->
```

## 两遍成文

第一遍只沿已审核的商业发动机和因果主链写清这门生意怎样运转。先让事件、客户、交易、收入、成本、现金、竞争和资本预期自然接续，不在每句话落笔时同时执行语言禁令。

完整初稿写完后，必须从头独立精修一次：

1. **说话位置**：作者的确定、怀疑和保留必须与`narrative_position`一致。公开披露不能写成亲历，推演不能伪装成事实。
2. **段落推进**：每段只承担事件、客户、交易、收入、成本、现金、竞争、反方或判断中的一个主要任务；后一段没有新增事实、因果或情景时合并或删除。
3. **商业主干**：尽早写清谁行动、谁付款、谁承担成本、谁得到现金和谁拥有议价权。抽象概念不能连续替代具体的人、钱、时间和选择。
4. **修辞姿势**：识别反复使用的先制造误解再翻案、同构排比、连续设问、投资黑话和固定金句。判断从正面说，依据紧跟；只有新事实真实改变作者判断时才保留转折。
5. **中文节奏**：财务说明过密时拆回自然语言，连续短判断像口号时合并；数字出现后立即说明它改变了什么，不能再用抽象句重复抬价。
6. **结尾试删**：分别试删最后两段。若核心变量、正反信号和失效条件仍完整，就在更早的位置结束。

这次精修由LLM结合全文完成，不建立固定中文禁词表，不调用脚本评价洞察、人格或风格。

## 数字协议

正文中的金额、比例、份额、增速、估值、排名和量化比较只能来自`numeric_claims`：

- 内容块前添加`<!-- DATA:N01 -->`，多个数字写`<!-- DATA:N01,N02 -->`；
- 原样使用`publish_text`，需要修改先回到数字账本；
- `exact`可写确定值，`range`只写区间，`attributed`明确归因，`omit`不得出现；
- 不混用时间、币种、分母、公司整体与业务分部；
- 自行计算必须保留公式与输入值；
- 无法解释的来源冲突不取平均，改写为区间、归因或删除。

HTML转换器负责移除DATA标记。

## 表达

- 作者负责选择、解释和判断，不逐段播报来源；
- 科技细节只保留理解商业结果所需的部分；
- 把使用者、决策者、付款者、成本承担者和最终受益者写清楚；
- 至少用一段自然语言讲清本题的收入方程，再用一段讲清收入怎样经过直接成本、固定投入和资本开支成为或无法成为现金；
- 每个“增长”都要追问来自价格、数量、频率、留存、结构还是并购，每个“壁垒”都要落到定价、成本、留存、周转或资本效率；
- 明确区分客户获得价值、公司取得收入、业务产生利润、股东获得回报四个层次；
- 事实、解释、推断和情景保持边界；
- 原话直接使用准确中文；
- 作者必须在判断中现身，不把“读者”当作正文里的第三方对象；需要拉近距离时自然使用“我、我们、咱们”，但不形成固定口头禅；
- 一句一段与中长段交替；
- 少量使用`>`、独立粗体句、列表和必要小标题；
- 最终Markdown和HTML不使用表格。需要比较多个变量时，改用短列表、逐项解释或连续的小段落，避免在手机和不同平台上挤压错位；
- 不把短期股价变化当作业务证明；
- 不使用“财富密码”“确定性机会”等煽动表述。

## 开头与结尾

开头从熟悉主体、反常结果、关键数字或读者正在犯的判断错误进入，尽快把科技新闻改写成一个关于客户、利润或产业权力的问题。

结尾不荐股、不喊口号。用最少文字留下核心变量、最值得等待的信号和判断失效条件。

## 篇幅

常用目标约四千二百至五千二百个读者可见字符，最低不得少于三千六百个。施工标记、Markdown符号、图片占位符和HTML标签不计入篇幅。

篇幅必须分布在商业推理主体，而不是用开头、结尾、背景资料或重复结论补足：

- 开头只完成事件进入、商业矛盾和阅读回报；
- 默认五至七章，每章通常约四百五十至七百个可见字符；
- 最薄章节不得少于三百五十个可见字符；
- 最厚章节不得超过最薄章节的约两倍；
- 客户与付款、收入质量、成本与单位经济性、现金与资本、竞争与价值归属都要获得足够解释空间；
- 最后一章只负责收束Spark、情景和观察框架，不能接收前文来不及展开的全部内容。

偏短时只补利润传导、因果、数字口径、反方路径和情景推演。某一章偏薄时补它缺失的“为什么”，不得把同一结论换词复述。

## HTML

先写`article/final_article.md`，再运行：

```bash
python skills/business-article/scripts/markdown_to_wechat_html.py --topic-dir /absolute/topic/path
```

生成唯一的`article/final_article_copy.html`：

- 全部可见文字15px；
- 内联CSS，不依赖页面背景；
- 明暗模式均清楚；
- 透明底的科技商业杂志风，不依赖整页或大面积背景色；用精密细线、数据轨道、矩形编号、局部侧边框和蓝、红、青、金等信息色建立层次；
- 章节标题、关键判断、引用、列表与图片占位必须形成不同视觉节奏，不能全页只有同一种标题块和普通段落；
- 数字、引用、列表、表格和代码块清晰；
- 图片只留下明确插入位置；
- 不出现账号名称、脚注和文末来源清单；
- 所有施工标记全部移除。
